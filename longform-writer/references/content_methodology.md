## 1. 選題方法論

### 選題交集模型

一個好選題 = 你的專業領域 + 讀者的普遍興趣 + 當下的時間節點

光是專業，可能曲高和寡；光是讀者興趣，可能流於膚淺；光是蹭熱點，可能曇花一現。三者結合，才容易找到最精準的引爆點。

### 選題來源

**X（Twitter）**：搜尋關鍵詞，抓一手資訊，關注博主和公司動態。
**Reddit**：看討論密度、問題類型與高共鳴留言。
**小紅書 / 即刻 / 微博 / 抖音 / B站**：看哪些話題真正破圈，哪些只是小圈層自嗨。
**讀者社群**：觀察群友的難點、痛點和重複出現的需求。

### HKR 質檢法

動筆前，每個選題至少要問自己三件事：
- **H (Happy)** 足夠有趣、有懸念？
- **K (Knowledge)** 有資訊量？
- **R (Resonance)** 能戳中情緒？

S 級選題三項兼備，及格至少兩項，只佔一項要重新審視，零項堅決放棄。

### 角色代入法

審視選題時代入不同角色：
- 一個很忙的普通使用者：能幫我省時間、解決具體麻煩嗎？
- 一個愛玩的朋友：夠有趣嗎？能讓我產生「臥槽還能這樣？」的驚訝嗎？
- 一個焦慮的學習者：能讓我學到新東西、有新角度嗎？

## 2. 選題分類與案例

### 按業務類型

**大模型技術**：大模型、演算法、Agent、程式設計工作流。
**AIGC 藝術**：AI 設計、影片、音樂、數字人、玩法創意。
**泛網路文化**：深度訪談、現象故事、觀點解讀、政策解讀。

### 按內容類型

**產品評測 + 推薦**：核心是實測和明確好惡。
**玩法 + 教程分享**：核心是帶讀者走完一個操作過程。
**現象訪談類**：核心是故事與洞察，而不是資訊堆砌。
**認知觀點**：核心是把事情講透，不是把話講大。
**AI 整活**：核心是親自做出一個好玩的東西，展示可能性。

### 按寫作原型

**調查實驗型**：親自下場做一件事，邊做邊把發現寫出來。寫法核心是過程敘事 + 層層發現 + 真實反應。

**產品體驗型**：拿到產品實際使用，帶著讀者一起體驗。寫法核心是場景驅動 + 真實感受 + 自然對比。

**現象解讀型**：從一個有趣現象出發，追問背後原因。寫法核心是好奇心驅動 → 研究 → 知識掉落 → 升維。

**工具分享型**：分享實用工具，但要用故事和情境引出，不要一上來就推薦清單。

## 3. 內容節奏

節奏不是文筆問題，是一套讓讀者一路往下讀的推進系統。

好的節奏像波動：每次圍繞主線偏出去一點點（讓讀者喘口氣、長見識、看案例），再用一句話拉回來繼續推進。

**扣主線句**要高頻出現——不需要長，一句就夠，但頻率要高。

**最忌諱**：突然偏離主線很遠再硬拽回來，讀者要花腦力順邏輯，心流會斷掉。

節奏優先順序：專業（底子）→ 觀點（方向）→ 主線（繩子）→ 節奏（牽引力）

## 4. 創意案例工作法

### 三類錨點

**熱點錨點**：當下最火的事件、電影、梗或社會話題。
**痛點錨點**：讀者最高頻、最頭疼的問題。
**炫技錨點**：工具本身最顛覆、最能讓人驚訝的功能。

### 包裝成微型故事

1. 亮出挑戰：想解決什麼問題？
2. 展示腦洞：想到什麼操作？
3. 秀出過程：怎麼一步步實現？
4. 引爆結果：最後那個讓人記住的作品或結論。

**準則**：案例必須同時有觀賞價值、創意價值和啟發價值。如果自己都提不起勁，就不要硬塞進稿子。
